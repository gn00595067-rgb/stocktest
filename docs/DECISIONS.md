## 2026-09-29 · 庫存已實現：改計算口徑，而非只改文案

- **選**：庫存損益頁的「已實現損益」KPI 改用 `get_realized_pnl_by_stock()`（全部股票、含已賣光）。
- **不選**：只在 caption 註明「僅計仍有庫存的股票」。
- **為什麼**：同事期望兩頁的已實現能對起來；只改文案，數字仍偏低、仍會被質疑。改口徑後同區間兩頁一致，且順手修掉「報酬率分子（僅持倉）／分母（全部）不一致」的隱性 bug。

## 2026-09-29 · aggregate_by 除零：用 float("nan")，不用 pd.NA、不引入 numpy

- **選**：`買進成本.replace(0, float("nan"))`。
- **不選**：維持 `pd.NA`（會轉 object dtype 讓 `.round()` 崩潰）；或引入 numpy 用 `np.where`。
- **為什麼**：`float("nan")` 保持整欄 float dtype，`.round(2)` 正常、無成本的股票顯示 NaN；一行改動、不新增相依、風險最低。

## 2026-09-29 · 交易輸入清空：加按鈕，不強改自動重置流程

- **選**：新增「🧹 清空輸入列」按鈕（複用既有 `te_rreset` 重置機制）。
- **不選**：直接改寫送出後的自動重置時序（尚未定位到為何未觸發，貿然改動可能引入賣出逐筆流程的回歸）。
- **為什麼**：先給同事一個確定有效的止痛工具；根因待可穩定重現後再處理，避免動到剛改過的多筆賣出逐筆配對邏輯。

## 2026-09-30 — 底價依升降單位「向上」進位，且不套當沖減半稅
- 選：取「可掛單、且賣了保證不虧」的最低價，並以一般證交稅 0.3%（ETF 0.1%）計算。
- 不選：顯示未進位的理論值（如 946.37），同事無法直接掛單；也不套當沖減半，因為庫存賣出多數不是當沖，用保守值才不會誤賣虧損。
