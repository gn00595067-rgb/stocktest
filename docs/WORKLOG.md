## 2026-09-29 — 同事回報三個損益／輸入問題，一次修掉

**做了什麼**
1. **庫存損益頁「已實現損益」偏低** → 改口徑。原本 KPI 只加總「仍有庫存」的股票（`build_portfolio_df` 在 `qty<=0` 時整列跳過），已全部賣光的標的其已實現損益完全沒被算進去，導致「近半年 1,761,385」竟然小於「已實現頁本月 2,635,554」（子集合反而較大＝鐵證漏算）。改為用 `get_realized_pnl_by_stock()` 以「全部股票、賣出日落在區間」口徑計算，並讓「總報酬率」分子分母同口徑。（`pages/1_庫存損益.py`）
2. **「依股票彙總」整頁崩潰 TypeError** → 一行修。`aggregate_by` 用 `.replace(0, pd.NA)` 會把欄位轉 object dtype，`.round(2)` 逐格套 `round()` 遇 `pd.NA` 就爆；只有某檔買進成本加總為 0（如全配股 price=0）時觸發。改用 `float("nan")` 保持 float dtype。（`reports/realized_report.py`）
3. **交易輸入送出後表單沒清空、要逐筆刪** → 加保險。買進送出後本應自動重置（`te_rreset` 機制），但同事流程未觸發；新增「🧹 清空輸入列」按鈕，一鍵回到一列空白，複用既有重置機制。（`pages/3_交易輸入.py`）

**為什麼**：同事（Peggy 姐測試）回報庫存已實現對不起來、彙總頁打不開、輸入賣出前要一筆筆刪買進列，三者都影響日常記帳。

**驗證**：`pytest` 57 passed（新增配股 price=0 的彙總回歸測試 `test_aggregate_by_handles_zero_cost_stock`）。

**下一步**：定位交易輸入「送出後未自動清空」根因——逐筆賣出模式送出只移除該賣出列、保留其他列，待同事能穩定重現後深挖 rerun 時序（已加清空按鈕止痛，非緊急）。

## 2026-10-01 — 同事回饋：投資績效 vs 庫存損益未實現不一致、底價疑慮、負數顏色

**做了什麼**
1. **修 bug：兩頁未實現口徑統一**。`compute_position_and_cost_by_stock` 預設 policy 由 `"CUSTOM"`（只看自定沖銷）改為 `"CUSTOM_PLUS_FIFO"`，投資績效頁兩處呼叫也明確傳入 `policy`。（`services/position_cost.py`、`reports/portfolio_report.py`、`pages/0_投資績效.py`；AI 問答助理、自定沖銷設定頁的持倉成本也一併受惠）
2. **自定沖銷設定頁加「失效規則」警示**：列出指向已刪除交易或跨股票的規則（目前正式資料有 26 條），提示到「已配對一覽」刪除重設。（`pages/5_自定沖銷設定.py`）
3. **底價說明加強**：庫存損益表格上方說明「底價≠均價進位」並附國巨實例；交易輸入表頭「底價 ⓘ」滑鼠停留顯示說明。庫存損益也註明「紅＝賺、綠＝賠（台股慣例）」。

**為什麼**
- 投資績效持倉成本只套自定沖銷，沒設規則（或規則失效）的賣出不扣成本，均價變成剩餘批次加權平均。以 Peggy姐 正式資料驗算：景碩 891.50 vs 943.75（差 99,275），合計差 99,721，正好是 -218.7萬 與 -228.7萬 的差距；景碩 9/1 四筆賣出的規則指向已刪除的買進 id 53–58。修後兩頁成本差為 0。
- 底價公式經驗算無誤：國巨 6,101 股、成本 5,302,479，賣 870 扣費稅後仍虧 12,422，873 才打平；同事心中的「底價」是均價進位，未計賣出約 0.34% 費稅。
- 顏色維持紅賺綠賠（理由見 DECISIONS）。

**驗證**：`pytest` 68 passed（新增 `tests/test_position_cost.py`：孤兒規則情境下 position_cost 與 build_portfolio_df 均價一致）；以正式試算表資料（唯讀載入）比對兩頁持倉成本差 0。
