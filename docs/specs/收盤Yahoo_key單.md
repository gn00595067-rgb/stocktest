# 收盤 Yahoo key 單 — 規格

> 狀態：MVP（2026-11-16）
> 需求來源：Elsa（LINE 2026-11-16）

## 1. 要解決什麼
公司同時在 Yahoo 奇摩投資組合記帳。Yahoo：
- 只有「日期、股數、成交價」三欄，**沒有手續費、證交稅、當沖**。
- 賣出一律**先進先出**（扣日期最早的買進；由華通截圖反推：賣 4000 股扣掉 11/04 的 4000 股）。

系統是自定沖銷，所以兩邊的已實現、庫存均價對不起來。Elsa 現在的做法：庫存只留「一整包」一列，要賣的那幾筆把日期改到最早讓 Yahoo 先沖掉。
她缺的是數字：**前一天的庫存今天賣掉多少股、成本多少；今天買賣多少；收盤後庫存幾股、均價多少**。以前要人工查沖哪幾筆，現在由系統判定，系統要告訴她。

## 2. 範圍（MVP）
- 新頁「收盤Yahoo key單」：選日期＋買賣人（一個 Yahoo 投資組合通常對一位買賣人）。
- 只列「當天有交易」的股票。
- 全部用**不含稅費**的價格（Yahoo 沒有稅費）；另列系統的不含稅費已實現讓她對數字，淨損益仍以系統為準。
- 不做：寫入 Yahoo、追溯 11 月中以前的已實現。

## 3. 每檔要給的數字
| 欄 | 說明 |
|---|---|
| 前一天庫存 股數／均價 | 當天以前的買賣沖銷後剩下的 |
| 今天買進 股數／均價 | 當天全部買進 |
| 今天賣出 股數／均價 | 當天全部賣出 |
| 沖掉以前庫存 股數／成本均價 | 今天的賣出配到「當天以前買進」的部分 |
| 沖掉今天買進 股數／成本均價 | 今天的賣出配到「當天買進」的部分（當沖） |
| 收盤後庫存 股數／均價 | |
| 已實現（不含稅費） | 系統配對的 (賣價−買價)×股數 加總 |

## 4. Yahoo 要長什麼樣（收盤後的目標狀態）
今天有賣出時：
- **A 買入**：股數＝今天沖掉的總股數（以前庫存＋今天買進），價格＝它們的成本均價。日期要比 B 早（通常就是把「前一天庫存那一包」改成 A，日期不動）。
- **B 買入**：今天日期，收盤後庫存股數＠收盤後均價。
- **C 賣出**：今天日期，今天賣出股數＠賣出均價（盤中逐筆 key 的賣出只要股數價格都對可以保留）。
- 盤中 key 的「今天買入」列要刪掉（已併進 A／B）。

今天只有買進：把前一天那一包改成收盤後庫存股數＠均價（或新增一筆今天的買入）。

為什麼已實現不會不見：被賣過的 A 和 C 以後都不動，隔天只改 B（沒被賣過）。Yahoo 先進先出時，每天的賣出剛好扣掉同一天建立的 A。

價格四捨五入到小數 2 位（Yahoo 欄位），會造成幾十元以內的差；頁面列出「Yahoo 會算出的已實現」與系統差多少。

## 5. 計算
- 交易只取「選定買賣人、日期 ≤ 選定日」，口徑同其他報表：`compute_matches(policy=DEFAULT_POLICY, 自定沖銷＋其餘先進先出)`。
- 配對中賣出日＝選定日的為「今天的沖銷」，依買進日 < 或 = 選定日分成「以前庫存」「今天買進」。
- 前一天庫存＝當天以前的買進扣掉「賣出日 < 選定日」的配對。
- 驗算：前一天成本 − 沖掉以前成本 ＋ 今天買進成本 − 沖掉今天成本 ＝ 收盤後成本（不含稅費）。

## 6. 驗收
- 用 Elsa 的華通例子：Yahoo 照 A/B/C key 完，已實現＝頁面的「Yahoo 會算出的已實現」，庫存均價＝收盤後均價。
- 待確認：新股當天買當天賣一部分（A、B 同一天）時 Yahoo 先扣哪筆。
