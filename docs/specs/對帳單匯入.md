## 1. 要解決什麼
- 現在要一筆一筆 key。券商盤後就有完整的成交明細，數字是 App 直接匯出的，一定正確。
- 盤後匯出的檔包含整段期間的**所有**交易，其中有幾筆可能白天已經手 key 了 → 要自動只補沒 key 的，不能重複算。
- 同一個檔可能下載好幾次、期間互相重疊 → 匯過的要自動排除。
- 賣出要決定沖哪幾筆買進，一筆一筆指定太累，要能一次選好統一的沖銷方式。

## 2. 範例檔格式
```
股名,日期,成交股數,淨收付,成交單價,成交價金,手續費,交易稅,稅款,委託書號,幣別,備註
聯電,2026/10/29,"1,000","-115,546",115.5,"115,500",46,0,0,A4233,台幣,
元大高股息,2026/10/27,17,-959,56.4,958,1,0,0,p016u,台幣,
```
**檔案數字一律照收**（證券 App 匯出，不做計算檢核、不用折數重算手續費）。

| 欄位 | 用法 |
|---|---|
| 股名 | 對主檔 `stock_master.name` 換股號（檔內沒有代號），要完全相同才算；對不到就列出來（見 §5） |
| 日期 | 西元 `YYYY/MM/DD` |
| 成交股數 | 去掉千分位；零股就是實際股數（17、50…） |
| 淨收付 | **負數＝買進、正數＝賣出**（檔內沒有買賣別欄。買進＝付出價金＋手續費；賣出＝收到價金－手續費－交易稅） |
| 成交單價 | 價格 |
| 手續費、交易稅 | 存進 `fee`、`tax`（當沖稅減半、零股最低手續費都已經算好） |
| 委託書號 | 存起來做防重複（見 §4） |
| 成交價金、稅款、幣別、備註 | 不使用（備註有內容就存進 `note`） |

**其他券商的變化（2026-11-03 國泰檔）**：
- 表頭前面可能有說明列（「根據您篩選後的結果，總計有33筆資料…」）→ 前 20 列裡找同時有「股名」「日期」「委託書號」的那列當表頭；空白列略過；錯誤訊息的列號照檔案實際列號。
- 欄名別名：「淨收付金額」＝淨收付、「成交價」＝成交單價（同檔已有正式名稱就不套）。多出的帳戶、買賣別、成本等欄不使用。
- 股名尾巴的 `*`（例「國巨*」）比對主檔時去掉。

檔案是**新到舊**排序；處理時改成「日期舊→新、同一天照檔案順序」，讓前幾天的買進先變成庫存，再拿來沖後面的賣出。

## 4. 只匯沒 key 的、排除重複匯入
### 4.1 資料：新表 `trade_refs`
比照 `sim_states`／`pledges`，`services/trade_ref_service.py` 第一次用到才建表。**不改 `db/models.py`、免 Reboot**。

| 欄位 | 說明 |
|---|---|
| user、trade_date、order_no | **主鍵**（委託書號每天重編，所以要帶日期；原樣保留大小寫，`k01C4` ≠ `k01c4`） |
| trade_id | 對應到哪筆交易。一筆手 key 的交易可能是好幾張委託合起來 key 的，所以**可以重複** |
| batch_id | 哪一次匯入（時間戳），給第二階段「復原這次匯入」用 |
| source | `import`＝匯入新增；`backfill`＝認出是手 key 的，把書號補上去 |

### 4.2 每一列怎麼判斷（依序，分組＝同買賣人＋同日＋同股＋同買賣方向）
1. **⏭️ 已匯入過**：`trade_refs` 已有這個（買賣人, 日期, 書號），而且對應的交易還在 → 略過。
   （交易被刪掉的就不算，刪錯後可以重新匯回來。）
2. **✋ 已手 key（一模一樣）**：同組裡有「還沒有書號」的交易，價格和股數完全相同 → 一對一認領、略過，並把書號補到那筆交易。
   同價同量有好幾筆時用數量配：檔內 3 筆、手 key 1 筆 → 認領 1 筆，另外 2 筆匯入。
3. **✋ 已手 key（合併 key）**：第 2 步做完後，同組還有沒認領的手 key 交易，且它們的**股數合計＝檔內剩下的股數合計**、
   **均價差 0.5% 以內**（例：分 3 張成交，手 key 時合成一筆 3,000 股、打均價）→ 整組視為已 key、略過，3 個書號都補到那筆。
   股數對但均價差很多（手 key 打錯價格）→ 歸第 4 步「要確認」，不默默留著錯的價格。
4. **⚠️ 要確認**：做完上面，同組**還剩**沒認領的手 key 交易（股數對不起來，例如手 key 打錯價格或股數）
   → 這組剩下的檔內列**預設不匯**，預覽並排顯示「手 key：聯電 115 × 1,000／對帳單：115.5 × 1,000」，讓人勾「仍要匯入」。
   寧可少匯讓人看，也不要自動重複算。
5. **🆕 新增**：同組完全沒有手 key 的交易 → 匯入。

- 只比對**同一個買賣人**的交易：替雅雲匯的檔，不會因為 Peggy 那天也買了聯電就被略過。
- 同一個檔裡同一個書號出現兩次、內容也一樣（拼檔重複）→ 只算一次。
- 手 key 的手續費／稅跟對帳單不一樣時：檔案數字才是對的。認領時勾「用對帳單的手續費／稅更新手 key 的交易」（**預設勾**），
  預覽列出會改哪幾筆、各差多少；合併 key 的用該組合計更新。

### 4.2.1 key 錯的修正、對帳單沒有的手 key（2026-11-06 Peggy／雅雲）
> 「若未來盤中先 key 入（沒有委託書號），在盤後把交易匯入，系統要能自動比對，不要重覆列入（key 錯的要修正，沒 key 的要補入）」

- 沒 key 的補入、key 對的不重複：§4.2 第 1～3、5 步本來就做到。
- **⚠️ 要確認的組改成三選一**（預設「先不處理」）：
  1. 先不處理：這次不匯（同原本）。
  2. ✏️ 手 key 打錯了：照對帳單修正那筆——手 key 那一筆改成對帳單這組的合計股數、加權均價、手續費、稅，書號補上（source＝`fix`）。
     **只有同組剩一筆手 key 時才有這個選項**（好幾筆不知道要改哪筆，請到仿Yahoo 自己改）。
     股數有變 → 這筆原本的沖銷配對清掉（同仿Yahoo 修改交易的口徑），畫面先提示。
  3. 手 key 那筆是另一筆交易：對帳單照樣匯入（原本的「勾了才匯」）。
- **手 key 了、但對帳單裡沒有的**：對帳單日期內、沒書號、沒被任何一列認領的手 key 交易，列在「⚠️ 手 key 了、但對帳單裡沒有」，
  多半是 key 錯股票／日期／買賣。**預設不刪**，勾了才刪（連同沖銷配對）；不是這個證券帳戶的交易不要勾。
- 修正與刪除先套用到記憶體裡的交易，再算當沖、沖銷、預估損益；寫入跟匯入同一個交易，失敗全部還原。

### 4.3 手動輸入時防重複（第二階段）
- 仿Yahoo／交易輸入的新增表單加選填「委託書號」；重複就提醒，勾確認後才能送出（只提醒不擋，跟質借同樣原則）。
- 手 key 通常比盤後匯入早，所以主要靠 §4.2 第 2～3 步在匯入時認出來；這一項等匯入用順了再加。

## 5. 匯入流程（畫面）
在「交易匯入」頁最上面新增「〇、券商對帳單（證券 App 匯出）」；舊的「一、」保留給有帳戶欄的其他格式。

1. **買賣人**：下拉選單，預設 Peggy姐，可改成雅雲或其他人。旁邊用大字顯示「目前要匯入：雅雲」，避免選錯人沒發現。
2. **上傳 CSV**。
3. **摘要**（放在預覽表上面）：共 29 筆 → 🆕 新增 20、✋ 已手 key 6、⏭️ 已匯入過 3、⚠️ 要確認 0；
   當沖 K 組；賣出 S 筆用「先進先出」沖銷；預估這次多出的已實現損益 ±X。
4. **預覽表**：狀態｜日期｜股號 股名｜買/賣｜股數｜價格｜手續費｜稅｜委託書號｜當沖｜沖銷到哪幾筆｜預估損益（賣出才有）。
   摘要下方「📊 預估損益分股看」：每檔股票的沖銷股數與預估損益（2 檔以上預設展開），並說明對不起來時去哪改
   （匯入前換沖銷方式；匯入後「自定沖銷設定」改配對；買進打錯到「股票輸入（仿Yahoo）」／「交易輸入」改）。2026-11-03 Elsa 回饋：只有總數，對不起來看不出是哪檔。
   預設只展開 🆕 和 ⚠️，其他的收起來。
   - 股名在主檔找不到：該列擋下並列出名稱，請先到「主檔設定」補上（MVP 不在這頁挑股號）。
5. **賣出沖銷方式**：有新賣出就出現（含全部是當沖時），見 §6、§7。有當沖時下方顯示「怎麼判斷當沖」說明。
6. **確認匯入**：寫 `trades`、`trade_refs`、`custom_match_rules`、更新手 key 稅費，全部在同一個交易裡，失敗就全部還原。
   沒有可新增的列時按鈕不能按。
7. 完成後顯示「已匯入 N 筆、補上書號 M 筆」，再到仿Yahoo 看持股。

## 5.1 少數幾筆算在別人帳上（2026-10-30 追加）
> Jonathan：「同一張對帳單匯入的，可能偶爾有幾筆交易要算在不同人的帳戶，但這是少數狀況。可以匯入時勾選是否要選擇匯入不同人帳戶，
> 但平常就是選單一個人，就全匯入就好。」

- 平常：畫面跟原本一樣，選一個人，全部匯給他。
- 勾「☐ 有幾筆要算在別人帳上」（預設不勾）→ 出現可編輯的表格，列出這次要處理的每一筆（已匯入過的不列），
  最後一欄「買賣人」預設是上面選的人，要改的那幾筆用下拉改成別人。
- 改了人之後，**每一筆都用它自己的買賣人判斷**：已手 key 的比對、當沖配對、賣出沖銷的庫存都只看那個人的交易
  （Peggy 的買和雅雲的賣不會配成當沖）。賣出統一沖銷方式全部人共用一種。
- 預覽表和摘要多一欄／一段「買賣人」：例「Peggy姐 20 筆、雅雲 1 筆」，按鈕寫「確認匯入 21 筆（Peggy姐 20、雅雲 1）」。
- 取消勾選 → 全部回到上面選的那個人。

### 跨人防重複
- 一份對帳單是同一個證券帳戶，委託書號在這份帳戶裡同一天不會重複，跟匯到誰無關。
  所以「已匯入過」改成**跨所有買賣人**比對：同日、同書號、而且對應交易的股票、買賣、價格、股數都一樣 → ⏭️ 已匯入過，並註明匯到誰
  （例：上次那筆匯給雅雲，這次預設選 Peggy姐 重匯，也不會重複算到 Peggy 帳上）。
- 要求內容一樣，是因為不同證券帳戶的書號有可能剛好相同；內容也一樣的機率極低。

## 6. 當沖配對
- 同買賣人、同股、同日有買也有賣 → 當沖。**資料庫裡當天已經有、還沒沖完的交易也算進來**（例：買進是白天手 key 的，賣出盤後匯入）。
- **先看證交稅判斷賣出是不是當沖**（2026-11-03 Elsa 回饋：先賣掉 420 股庫存、再買 60 股，被誤配成當沖）：
  賣出稅＝價金 0.3%（容許 1 元）→ 一般賣出，不配當沖，走 §7 沖舊庫存；＝0.15% → 當沖。
  ETF（00 開頭，0.1% 不減半）、稅是 0、部分當沖（介於中間）看不出來 → 照舊：同日有買就配。
- 當天買賣股數取小的那邊先互沖，寫成 `CustomMatchRule`，兩邊 `is_daytrade=True`。
- **當天買比當沖賣多時，沖哪幾筆照 §7 選的方式**（2026-11-04 Elsa 回饋：有庫存、當天買 83 張賣 50 張，畫面不能選沖哪幾筆、也沒說原則）：
  先進先出＝照成交順序；保守＝當天價高的先沖；樂觀＝價低的先沖；均價＝最接近當天買進均價的先沖；不指定＝照成交順序（當沖一定要配）。
  畫面用一句說明寫出這個原則。
- **當沖的賣出也可以沖以前幾天的庫存**（2026-11-04 Jonathan：「請改成當沖賣也可以配對以前幾天買的沖銷配對」）：
  有當沖時多一個選項「當沖的賣出要沖哪裡的買進」：
  1. 以前的庫存＋當天的買進都可以（**預設**）→ 新匯入的當沖賣出跟一般賣出一樣走 §7，從全部庫存照選的方式挑（先進先出就會先沖以前的）。
     賣出仍標當沖（稅是當沖稅，重算稅費才不會變 0.3%）；買進不標。手 key 的既有賣出配上這次的買進，維持當沖互沖。
  2. 只沖當天的買進 → 原本做法，不動原本庫存。
- 摘要改顯示「當沖賣出 N 筆」（原本是「當沖 N 組」，選 1 時已不是互沖組）。
- 多出來的：買多 → 剩的變一般庫存；賣多 → 剩的賣出走 §7 統一沖銷。

## 7. 賣出統一沖銷方式
- 扣掉當沖後還剩的賣出，匯入前選一種方式，**直接寫成自定沖銷規則**（之後頁面換計算方式，損益也不會變）：
  1. 先進先出（預設）　2. 保守：成本高的先沖　3. 樂觀：成本低的先沖　4. 均價：最接近平均成本的先沖　5. 不指定：不寫規則
- 能沖的庫存＝該買賣人目前還沒沖完的買進（`get_open_buy_lots`）＋這次檔內日期較早的買進。直接重用 `pnl_engine.compute_matches` 的排序，不另寫一套。
- 賣出股數超過庫存：能沖多少就沖多少，預覽標紅「庫存不足 X 股」；仍可匯入（可能還有更早的買進沒 key）。
- 有質押且賣出超過可動用股數：沿用質借的提醒，只提醒不擋。
- 已手 key、本來就有沖銷規則的賣出不會動。
- 想個別改：匯入後到「自定沖銷設定」頁改。

### 7.1 少數幾檔另外指定（2026-11-10 Elsa：「匯入 11/10 A.B.C.D.E 五檔，A.B.D.E 要沖成本高，但 C 要沖指定的特定交易」）
- 統一方式下面多一個勾選「有幾檔股票要另外指定沖哪幾筆買進」，**預設不勾**，不勾＝跟以前一模一樣。
- **以股票為單位**（Elsa：「今天賣出聯電 25 張，我要沖成本 20 張 100 元跟 5 張 101 的」，她是整檔想，不是一筆一筆賣出想）：
  - 這次只有一檔有賣出 → 直接出現；多檔 → 先多選要另外指定的股票。
  - 每檔一個「怎麼沖」（預設**自己挑買進**，也可改先進先出／保守／樂觀／均價／不指定，套用到這檔全部賣出）。
  - 自己挑：一張這檔可沖的買進表（還沒沖完、成交日不晚於最晚那筆賣出；新的在上面，跟對帳單一樣），填「沖這筆幾股」。
  - 填好後 `allocate_picks` 自動分給這檔的各筆賣出：賣出照日期／順序、挑的買進照日期／順序依序配，買進不能晚於賣出。
  - 合計 < 這檔賣出股數：差的照統一方式補沖（畫面寫出來）；某筆填超過剩餘、合計超過賣出、日期配不到 → 紅字，確認鈕不能按。
- 計算順序：當沖 → 自己挑的 → 其餘賣出照日期逐筆、各用自己的方式從剩下的庫存挑（自己挑的先佔掉買進）。
- 版本紀錄：第一版是逐筆賣出的表、要點格子改方式才出現買進；第二版改成先選賣出。Elsa 兩版都找不到地方選 → 第三版改以股票為單位。
- 程式：`plan_sell_matches(..., overrides={賣出 tmp_id: 方式})`、`pending_sells`、`available_buys`、`allocate_picks`。

### 7.2 庫存不夠時，不夠的股數拆給別的買賣人（2026-11-11 Elsa）
> 「要沖短線，但賣出股數高於短線庫存股數時，賣出是真實存在的，系統可否自動問庫存不夠，是否要沖 P 或豪或雲？因為 Peggy 姐不可能去拆對帳單。」
> 實例：P11月短線 11/11 賣 5340 穩懋，但短線帳沒有穩懋（是 Peggy姐 10 月買的），她只好把同一份對帳單拆兩次匯。
- 匯入前先用先進先出試算（當沖＋從庫存沖）哪幾筆賣出庫存不夠；有的話出現「⚠️ 庫存不夠的賣出」區塊，每筆一個選單：
  「不夠的 N 股記到誰」→ 先不處理（預設，維持庫存不足）／其他買賣人（後面附「這檔可沖 X 股」，到賣出日為止）。
- 選了人：那筆賣出**拆成兩筆**——原本的人留「股數−N」、選的人記 N 股；手續費、稅照股數比例拆（四捨五入，合計不變）；
  兩筆同一個委託書號（`trade_refs` 主鍵含買賣人，不衝突；再匯同一份檔時兩邊都認得出是已匯入過）。
- 拆出來的那筆照選的人自己的庫存配對（當沖判斷、統一／另外指定的沖銷方式都照常）。預覽表出現「買賣人」欄。
- 限制：沒有委託書號的對帳單用內容比對防重複，拆過的再匯一次會變「要確認」（股數對不起來），不會重複寫入。
- 庫存不足的提示一律寫「股號 股名」（Elsa：「背不起來 5340 是哪支」）。

### 7.3 沖銷方式「成本高但不賠」（2026-11-11 Elsa：「沖短線成本高的，但不要賠」）
- 每筆賣出：含手續費、稅算**不賠**的買進裡，成本高的先沖；不賠的不夠沖時，剩下的從**賠最少**（成本低）的開始。
- 「不賠」＝買進價 ≤ 賣價 × (1 − 0.1425% − 0.3%) ÷ (1 + 0.1425%)（約 ×0.9943）。手續費用公定費率不打折＝最保守：
  算進來的一定不賠；打折後其實小賺一點的那幾筆可能被當成會賠而排在後面。
- 當沖配當天買進時，用當天賣出的均價判斷。統一方式、另外指定（§7.1）都可選。
- 只寫成匯入時的自定沖銷規則；各頁面的計算方式選單沒有加（目前沒需求）。
- 程式：`pnl_engine.noloss_order`、`NOLOSS_FACTOR`；策略名 `NOLOSS`。
