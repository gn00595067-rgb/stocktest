     先列清單給 Jonathan 確認，尤其 `6208` 那檔要分清楚是日揚還是富邦台50（看成交價就分得出來）。

## 1. 要解決什麼
- 現在要一筆一筆 key。券商盤後就有完整的成交明細，數字是 App 直接匯出的，一定正確。
- 盤後匯出的檔包含整段期間的**所有**交易，其中有幾筆可能白天已經手 key 了 → 要自動只補沒 key 的，不能重複算。
- 同一個檔可能下載好幾次、期間互相重疊 → 匯過的要自動排除。
- 賣出要決定沖哪幾筆買進，一筆一筆指定太累，要能一次選好統一的沖銷方式。

## 2. 範例檔格式
```
股名,日期,成交股數,淨收付,成交單價,成交價金,手續費,交易稅,稅款,委託書號,幣別,備註
聯電,2026/10/29,"1,000","-115,546",115.5,"115,500",46,0,0,A4233,台幣,
元大高股息,2026/10/27,17,-959,56.4,958,1,0,0,p016u,台幣,
```
**檔案數字一律照收**（證券 App 匯出，不做計算檢核、不用折數重算手續費）。

| 欄位 | 用法 |
|---|---|
| 股名 | 對主檔 `stock_master.name` 換股號（檔內沒有代號），要完全相同才算；對不到就列出來（見 §5） |
| 日期 | 西元 `YYYY/MM/DD` |
| 成交股數 | 去掉千分位；零股就是實際股數（17、50…） |
| 淨收付 | **負數＝買進、正數＝賣出**（檔內沒有買賣別欄。買進＝付出價金＋手續費；賣出＝收到價金－手續費－交易稅） |
| 成交單價 | 價格 |
| 手續費、交易稅 | 存進 `fee`、`tax`（當沖稅減半、零股最低手續費都已經算好） |
| 委託書號 | 存起來做防重複（見 §4） |
| 成交價金、稅款、幣別、備註 | 不使用（備註有內容就存進 `note`） |

檔案是**新到舊**排序；處理時改成「日期舊→新、同一天照檔案順序」，讓前幾天的買進先變成庫存，再拿來沖後面的賣出。

## 4. 只匯沒 key 的、排除重複匯入
### 4.1 資料：新表 `trade_refs`
比照 `sim_states`／`pledges`，`services/trade_ref_service.py` 第一次用到才建表。**不改 `db/models.py`、免 Reboot**。

| 欄位 | 說明 |
|---|---|
| user、trade_date、order_no | **主鍵**（委託書號每天重編，所以要帶日期；原樣保留大小寫，`k01C4` ≠ `k01c4`） |
| trade_id | 對應到哪筆交易。一筆手 key 的交易可能是好幾張委託合起來 key 的，所以**可以重複** |
| batch_id | 哪一次匯入（時間戳），給第二階段「復原這次匯入」用 |
| source | `import`＝匯入新增；`backfill`＝認出是手 key 的，把書號補上去 |

### 4.2 每一列怎麼判斷（依序，分組＝同買賣人＋同日＋同股＋同買賣方向）
1. **⏭️ 已匯入過**：`trade_refs` 已有這個（買賣人, 日期, 書號），而且對應的交易還在 → 略過。
   （交易被刪掉的就不算，刪錯後可以重新匯回來。）
2. **✋ 已手 key（一模一樣）**：同組裡有「還沒有書號」的交易，價格和股數完全相同 → 一對一認領、略過，並把書號補到那筆交易。
   同價同量有好幾筆時用數量配：檔內 3 筆、手 key 1 筆 → 認領 1 筆，另外 2 筆匯入。
3. **✋ 已手 key（合併 key）**：第 2 步做完後，同組還有沒認領的手 key 交易，且它們的**股數合計＝檔內剩下的股數合計**、
   **均價差 0.5% 以內**（例：分 3 張成交，手 key 時合成一筆 3,000 股、打均價）→ 整組視為已 key、略過，3 個書號都補到那筆。
   股數對但均價差很多（手 key 打錯價格）→ 歸第 4 步「要確認」，不默默留著錯的價格。
4. **⚠️ 要確認**：做完上面，同組**還剩**沒認領的手 key 交易（股數對不起來，例如手 key 打錯價格或股數）
   → 這組剩下的檔內列**預設不匯**，預覽並排顯示「手 key：聯電 115 × 1,000／對帳單：115.5 × 1,000」，讓人勾「仍要匯入」。
   寧可少匯讓人看，也不要自動重複算。
5. **🆕 新增**：同組完全沒有手 key 的交易 → 匯入。

- 只比對**同一個買賣人**的交易：替雅雲匯的檔，不會因為 Peggy 那天也買了聯電就被略過。
- 同一個檔裡同一個書號出現兩次、內容也一樣（拼檔重複）→ 只算一次。
- 手 key 的手續費／稅跟對帳單不一樣時：檔案數字才是對的。認領時勾「用對帳單的手續費／稅更新手 key 的交易」（**預設勾**），
  預覽列出會改哪幾筆、各差多少；合併 key 的用該組合計更新。

### 4.3 手動輸入時防重複（第二階段）
- 仿Yahoo／交易輸入的新增表單加選填「委託書號」；重複就提醒，勾確認後才能送出（只提醒不擋，跟質借同樣原則）。
- 手 key 通常比盤後匯入早，所以主要靠 §4.2 第 2～3 步在匯入時認出來；這一項等匯入用順了再加。

## 5. 匯入流程（畫面）
在「交易匯入」頁最上面新增「〇、券商對帳單（證券 App 匯出）」；舊的「一、」保留給有帳戶欄的其他格式。

1. **買賣人**：下拉選單，預設 Peggy姐，可改成雅雲或其他人。旁邊用大字顯示「目前要匯入：雅雲」，避免選錯人沒發現。
2. **上傳 CSV**。
3. **摘要**（放在預覽表上面）：共 29 筆 → 🆕 新增 20、✋ 已手 key 6、⏭️ 已匯入過 3、⚠️ 要確認 0；
   當沖 K 組；賣出 S 筆用「先進先出」沖銷；預估這次多出的已實現損益 ±X。
4. **預覽表**：狀態｜日期｜股號 股名｜買/賣｜股數｜價格｜手續費｜稅｜委託書號｜當沖｜沖銷到哪幾筆。
   預設只展開 🆕 和 ⚠️，其他的收起來。
   - 股名在主檔找不到：該列擋下並列出名稱，請先到「主檔設定」補上（MVP 不在這頁挑股號）。
5. **賣出沖銷方式**：有非當沖的賣出才出現（見 §7）。
6. **確認匯入**：寫 `trades`、`trade_refs`、`custom_match_rules`、更新手 key 稅費，全部在同一個交易裡，失敗就全部還原。
   沒有可新增的列時按鈕不能按。
7. 完成後顯示「已匯入 N 筆、補上書號 M 筆」，再到仿Yahoo 看持股。

## 5.1 少數幾筆算在別人帳上（2026-10-30 追加）
> Jonathan：「同一張對帳單匯入的，可能偶爾有幾筆交易要算在不同人的帳戶，但這是少數狀況。可以匯入時勾選是否要選擇匯入不同人帳戶，
> 但平常就是選單一個人，就全匯入就好。」

- 平常：畫面跟原本一樣，選一個人，全部匯給他。
- 勾「☐ 有幾筆要算在別人帳上」（預設不勾）→ 出現可編輯的表格，列出這次要處理的每一筆（已匯入過的不列），
  最後一欄「買賣人」預設是上面選的人，要改的那幾筆用下拉改成別人。
- 改了人之後，**每一筆都用它自己的買賣人判斷**：已手 key 的比對、當沖配對、賣出沖銷的庫存都只看那個人的交易
  （Peggy 的買和雅雲的賣不會配成當沖）。賣出統一沖銷方式全部人共用一種。
- 預覽表和摘要多一欄／一段「買賣人」：例「Peggy姐 20 筆、雅雲 1 筆」，按鈕寫「確認匯入 21 筆（Peggy姐 20、雅雲 1）」。
- 取消勾選 → 全部回到上面選的那個人。

### 跨人防重複
- 一份對帳單是同一個證券帳戶，委託書號在這份帳戶裡同一天不會重複，跟匯到誰無關。
  所以「已匯入過」改成**跨所有買賣人**比對：同日、同書號、而且對應交易的股票、買賣、價格、股數都一樣 → ⏭️ 已匯入過，並註明匯到誰
  （例：上次那筆匯給雅雲，這次預設選 Peggy姐 重匯，也不會重複算到 Peggy 帳上）。
- 要求內容一樣，是因為不同證券帳戶的書號有可能剛好相同；內容也一樣的機率極低。

## 6. 當沖配對
- 同買賣人、同股、同日有買也有賣 → 當沖。**資料庫裡當天已經有、還沒沖完的交易也算進來**（例：買進是白天手 key 的，賣出盤後匯入）。
- 當天買賣股數取小的那邊先互沖，寫成 `CustomMatchRule`，兩邊 `is_daytrade=True`。同一天有好幾個價格時，照檔案順序一對一往下配。
- 多出來的：買多 → 剩的變一般庫存；賣多 → 剩的賣出走 §7 統一沖銷。

## 7. 賣出統一沖銷方式
- 扣掉當沖後還剩的賣出，匯入前選一種方式，**直接寫成自定沖銷規則**（之後頁面換計算方式，損益也不會變）：
  1. 先進先出（預設）　2. 保守：成本高的先沖　3. 樂觀：成本低的先沖　4. 均價：最接近平均成本的先沖　5. 不指定：不寫規則
- 能沖的庫存＝該買賣人目前還沒沖完的買進（`get_open_buy_lots`）＋這次檔內日期較早的買進。直接重用 `pnl_engine.compute_matches` 的排序，不另寫一套。
- 賣出股數超過庫存：能沖多少就沖多少，預覽標紅「庫存不足 X 股」；仍可匯入（可能還有更早的買進沒 key）。
- 有質押且賣出超過可動用股數：沿用質借的提醒，只提醒不擋。
- 已手 key、本來就有沖銷規則的賣出不會動。
- 想個別改：匯入後到「自定沖銷設定」頁改。
