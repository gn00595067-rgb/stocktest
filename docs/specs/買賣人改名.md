# 買賣人改名 — 規格

> Elsa 2026-11-04：「編輯分頁本來我入帳是 KEY 陳小姐，但後來想改成美美，但我只能改下面分頁名稱，上面誰的帳不能改，我不確定未來這會影響到什麼？」
> Jonathan 確認：陳小姐＝美美，是**同一個人改名**，她的交易要整個跟過去。

## 1. 要解決的問題
- 「這是誰的帳」下拉只能換成**別人**，換過去之後原本 key 在陳小姐名下的交易不會跟著走。
- 只改「分頁名稱」只是標籤，帳還是陳小姐的。同事不知道兩者差別。

## 2. 操作（MVP）
- 位置：仿Yahoo「編輯此分頁」對話框，「這是誰的帳」下面一個收起來的區塊「✏️ 幫『陳小姐』改名字」（只有管理者看得到）。
- 輸入新名字 → 按「改名」→ 這個人的所有資料一次改成新名字，對話框關掉、整頁更新。
- 說明文字：「交易、手續費折數、質押、分頁、權限綁定全部跟著改，數字不變。」

## 3. 會改到的資料（同一個資料庫交易，失敗全部還原）
| 表 | 欄位 |
|---|---|
| trades | "user" |
| cashflows | "user" |
| traders | name（手續費折數在同一列，跟著走） |
| user_trader_bindings | trader_name |
| portfolio_groups | trader；分頁名稱剛好等於舊名字的也一起改 |
| manual_figures | trader |
| pledges | trader（表存在才改） |
| trade_refs | "user"（表存在才改） |

不改：庫存模擬頁的存檔（sim_states，JSON 裡的人名；只是模擬設定）。

## 4. 擋下的情況
- 新名字空白、超過 50 字、跟舊名字一樣。
- 新名字**已經有人用**（主檔或交易裡有）：擋下，提示「這是合併兩個人，不是改名」。合併不在 MVP。
