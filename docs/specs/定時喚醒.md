# 定時喚醒（避免老闆早上開 app 等 50 秒）

## 需求（老闆 2026-10-23）
- 用平板打開 app 大約 50 秒才有畫面。
- 原因：Streamlit Community Cloud 閒置 **12 小時**沒有使用者就讓 app 睡覺；前一天收盤後沒人開，隔天早上第一個開的人要等它重新開機。Streamlit 沒有「付費不睡」的方案。
- 程式本身不慢：本機實測載入股票清單、讀交易、抓 52 檔報價合計約 5 秒。

## 設計
- GitHub Actions（`.github/workflows/wake-app.yml`）平日台灣早上自動「用瀏覽器打開」app 一次。
- **要用真的瀏覽器**（Playwright 無頭 Chromium），不能只用 curl：Streamlit 靠瀏覽器建立即時連線才算「有人在用」；app 在睡時還要按「Yes, get this app back up!」才會開機。
- 腳本 `scripts/wake_app.py`：打開網址 → 有喚醒按鈕就按 → 等到 app 畫面（登入頁的密碼框或 stApp）出現，最多等 4 分鐘；等不到就讓 workflow 失敗，GitHub 寄信。
- app 網址放 repo **Variable** `STREAMLIT_APP_URL`（不是秘密；不寫死在程式裡）。沒設就跳過不跑。
- 時間：台灣 07:30 與 08:30（cron 用 UTC，週日～週四 23:30、週一～週五 00:30）。GitHub 排程常延遲幾分鐘到半小時，排兩次保險。叫醒一次就能撐 12 小時，涵蓋整個上班時間。

## 不做（先不做）
- 不搬主機（Render 等每月約 7 美元）；喚醒後仍常遇到慢再考慮。
- 不登入、不碰任何資料；只打開登入頁。

## 已知限制
- 公開 repo 連續 60 天沒有 commit，GitHub 會自動停用排程（會寄信通知），到 Actions 頁按 Enable 即可。
- Streamlit Cloud 拉新版或平台維護時仍會重開，那次會慢。
